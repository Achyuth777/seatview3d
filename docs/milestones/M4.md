# M4 Data and accounts

## What changed

**Data model** (migration `005`, additive only):
- `provider_links` holds the cinema's showtimes link, its source (directory or admin) and when it was verified. Admin links survive the directory sync.
- `layout_verifications` records each verification of an auditorium. "Verified layout" now needs a current record for that exact auditorium. A flag alone shows "Illustrative".
- Screenings record `fetched_at`. Feed state records the last failure and an expiry time. Cached times past their expiry show "may be out of date".

**Imports:**
- Idempotent: screening IDs hash the provider key, and a repeated import updates rather than duplicates.
- Past shows drop out by their Asia/Kolkata start time.
- A provider failure changes nothing.
- An empty answer for a cinema that still has shows is kept and noted, never treated as cancellations.

**Accounts:**
- Registration sends a confirmation link. Saving, favourites and ticket import need a confirmed email.
- Password reset: the link works once and expires in an hour, and using it signs the account out on every device.
- Session lifetime is set by `SESSION_HOURS`.

**Alerts:**
- An import that changes or removes a saved show writes one alert per user, show and change, in the same transaction.
- Fetching alerts marks them delivered in the same statement, so each is delivered exactly once.
- Profile shows the old time, the new time and a link to other shows at that cinema.

**Email:** a simulated outbox (`mail_outbox`). Nothing is sent, because no email provider is connected. A development-only reader serves test addresses (`@example.com` or `@example.test`) and is refused in production. Email reminders stay disabled until real delivery exists, and the server rejects turning them on.

**Distinct kinds:** saved shows carry a "Saved show" label, demo tickets keep their CNF stamp under "Demo tickets · No payment", and confirmed provider bookings have their own dashed section.

## Tests that ran

- **Vitest, `tests/accounts-alerts.test.ts`:** 8 passed. Covers verification gating with single-use links, reset with sign-out everywhere and link expiry, session expiry, reminders refused, outbox limited to test addresses, alerts exactly once through an outage, an empty answer, a repeated import and a real change, cache expiry, admin links surviving sync, and verification records.
- **Vitest, full suite:** 111 earlier tests still pass. The migration tests now read the version list from the folder.
- **Playwright on PostgreSQL (`seatview_test`), 1440×900 and 390×844:** 8 passed.
  - Registration needs confirmation, with no save stars until then.
  - A reset signs out a second browser session.
  - **Failure: a tampered or expired session** drops to signed out, and the API returns 401.
  - Profile, home city, languages, favourites and saved shows persist into a second session.
  - A temporary city leaves the home city unchanged.
  - The three kinds of item look different.

## What failed and how it was fixed

- The first browser run failed because the Profile page has two "Name" and "Email" fields (sign-in and demo checkout). The tests now target the account form.
- The `seatview` role cannot create databases, so end-to-end runs use the existing throwaway `seatview_test`. A reset script refuses any database not ending in `_test`.
